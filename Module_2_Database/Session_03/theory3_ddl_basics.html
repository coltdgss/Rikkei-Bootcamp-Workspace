Session 03 · SQL cơ bản & Ngôn ngữ định nghĩa dữ liệu (DDL)

Nắm vững các câu lệnh cấu trúc DDL (CREATE, ALTER, DROP, TRUNCATE), hệ thống kiểu dữ liệu MySQL 8.0 chuẩn và các ràng buộc toàn vẹn cơ sở dữ liệu quan trọng nhất.

1 Bản chất của DDL (Data Definition Language)

DDL là nhóm lệnh dùng để xây dựng, thay đổi và phá hủy cấu trúc của các đối tượng trong cơ sở dữ liệu (Database, Table, View, Index, Stored Procedure). Khác với DML (dữ liệu bên trong dòng), DDL tác động trực tiếp lên phần khung (Schema).

Lệnh DDL Mục đích sử dụng Cú pháp mẫu MySQL 8.0 Lưu ý quan trọng
CREATE Tạo mới cơ sở dữ liệu hoặc bảng CREATE TABLE ten_bang (...) Nên kèm IF NOT EXISTS để tránh lỗi trùng lặp.
ALTER Sửa đổi cấu trúc (thêm/sửa/xóa cột, khóa) ALTER TABLE bang ADD/MODIFY/DROP ... Không làm mất dữ liệu hiện có nếu kiểu dữ liệu tương thích.
DROP Xóa hoàn toàn bảng/CSDL khỏi hệ thống DROP TABLE IF EXISTS ten_bang; Mất toàn bộ cấu trúc và dữ liệu vĩnh viễn, không thể ROLLBACK!
TRUNCATE Xóa sạch toàn bộ bản ghi nhưng giữ lại khung bảng TRUNCATE TABLE ten_bang; Nhanh hơn DELETE rất nhiều vì reset lại con trỏ AUTO_INCREMENT.

2 6 Ràng Buộc Toàn Vẹn Cốt Tử (Integrity Constraints)

Ràng buộc là các quy tắc do hệ quản trị CSDL MySQL áp đặt lên các cột nhằm đảm bảo tính chính xác, nhất quán và tin cậy của dữ liệu.

🔑 1. PRIMARY KEY (Khóa chính)

Định danh duy nhất cho mỗi bản ghi trong bảng. Tự động bao gồm cả hai tính chất: NOT NULL và UNIQUE. Mỗi bảng chỉ có duy nhất 1 khóa chính (có thể là đơn cột hoặc tổ hợp nhiều cột).

🔗 2. FOREIGN KEY (Khóa ngoại)

Tạo mối liên kết giữa 2 bảng (bảng con tham chiếu tới khóa chính của bảng cha). Ngăn chặn việc tạo dữ liệu "mồ côi" không có bản ghi cha tương ứng.

🚫 3. NOT NULL

Bắt buộc cột đó phải có giá trị khi thêm mới bản ghi. Tuyệt đối không cho phép để trống trường thông tin quan trọng.

💎 4. UNIQUE

Đảm bảo tất cả các giá trị trong cột không được phép trùng lặp (ví dụ: Số điện thoại, Mã định danh CCCD, Email tài khoản).

✅ 5. CHECK

Kiểm tra biểu thức logic trước khi lưu. Chỉ bản ghi thỏa mãn điều kiện mới được ghi vào đĩa (ví dụ: CHECK (gia_tien > 0), CHECK (diem >= 0 AND diem <= 10)).

⚙️ 6. DEFAULT

Gán giá trị mặc định cho cột nếu câu lệnh INSERT không truyền dữ liệu (ví dụ: DEFAULT 'Dang_hoc', DEFAULT CURRENT_TIMESTAMP).

3 Ví Dụ Thực Hành Tạo Bảng Chuẩn MySQL 8.0

Dưới đây là khối lệnh DDL tạo cơ sở dữ liệu trường học chuẩn mực với đầy đủ quan hệ 1-N và các ràng buộc toàn vẹn:

-- Tạo Database mới nếu chưa có
CREATE DATABASE IF NOT EXISTS QuanLyTruongHoc;
USE QuanLyTruongHoc;

-- Bảng Cha: LopHoc (1)
CREATE TABLE LopHoc (
    ma_lop VARCHAR(20) PRIMARY KEY,                   -- Khóa chính
    ten_lop VARCHAR(100) NOT NULL,                    -- Tên lớp (bắt buộc)
    nien_khoa VARCHAR(20) DEFAULT '2025-2026',        -- Giá trị mặc định
    so_luong_toi_da INT DEFAULT 40 CHECK (so_luong_toi_da > 0) -- Ràng buộc CHECK
);

-- Bảng Con: SinhVien (N)
CREATE TABLE SinhVien (
    ma_sinh_vien VARCHAR(20) PRIMARY KEY,             -- Khóa chính sinh viên
    ho_va_ten VARCHAR(100) NOT NULL,                  -- Họ tên
    ngay_sinh DATE NOT NULL,                          -- Ngày sinh
    gioi_tinh VARCHAR(10) CHECK (gioi_tinh IN ('Nam', 'Nu', 'Khac')),
    email VARCHAR(100) UNIQUE,                        -- Email không trùng lặp
    diem_dau_vao DECIMAL(4,2) CHECK (diem_dau_vao BETWEEN 0 AND 10),
    ma_lop VARCHAR(20) NOT NULL,                      -- Khóa ngoại nối về LopHoc
    CONSTRAINT fk_sinhvien_lophoc FOREIGN KEY (ma_lop) REFERENCES LopHoc(ma_lop)
        ON UPDATE CASCADE 
        ON DELETE RESTRICT
);
⚠️ Bẫy Điểm Thi Cần Tránh: Khi viết lệnh CREATE TABLE, bảng nào được tham chiếu (Bảng Cha như LopHoc) phải được tạo TRƯỚC bảng chứa khóa ngoại (Bảng Con như SinhVien). Nếu tạo bảng con trước, MySQL sẽ báo lỗi Error 1215: Cannot add foreign key constraint ngay lập tức!
